# 工作流契约与发布门禁

## 1. 运行模式

| 模式 | 初始输入 | 允许继续生成 Skill 的条件 |
|---|---|---|
| 已知场景 | 视频来源 + 目标场景 | 摄取完成且目标场景有课程证据 |
| 场景发现 | 视频来源 | 完成摄取、列出候选场景并由用户选定 |

不要在课程尚未摄取时凭标题猜测场景。用户指定的场景如果在课程中没有足够证据，报告不匹配，不要强行生成。

## 2. 状态与必需产物

| 状态 | 必需产物 | 成功条件 |
|---|---|---|
| `initialized` | `run_manifest.json` | 唯一临时目录创建成功 |
| `acquired` | 归档视频、URL 的 `.info.json` | 文件非空且 ffprobe 可读 |
| `transcribed` | 结构化 ASR segments | 转写非空、时间戳有效 |
| `evidence_extracted` | 代表帧、多模态/OCR通道、IR | IR 校验通过 |
| `methodology_extracted` | `methodology.json` | 来源引用全部存在 |
| `skill_specified` | `skill-spec.json` | 行为规范校验通过 |
| `skill_generated` | 候选 Skill 目录 | 候选规范与冻结规范一致 |
| `testing` | 冻结测试集、每轮输出 | 所有必需测试均被执行 |
| `passed` | `test-report.json` | 最终轮所有测试全部通过 |
| `published` | 最终 Skill 目录 | 原子发布并复验通过 |
| `cleanup_pending` | 清理预览 | 用户尚未授权或尚未执行 |
| `cleaned` | 更新后的 Manifest | 授权目标全部逐项处理 |

失败状态命名为 `<阶段>_failed`，并记录 `last_error`、失败产物和可恢复点。

## 3. 硬门禁

- 无有效转写：停止。视觉信息不能替代完整方法论转写。
- 目标场景未确定：停止在方法论提炼之后，不生成混合场景 Skill。
- 来源引用不存在：方法论校验失败。
- `skill-spec.json` 缺失、步骤漂移或阈值被弱化：规范校验失败。
- 课程证据与执行模板未隔离：候选 Skill 校验失败。
- 候选 Skill 内的规范哈希与冻结规范不一致：候选 Skill 校验失败。
- 任一必需 Mock 未通过：测试报告不得标记 `passed`。
- `test-report.final_status != passed`：发布脚本必须拒绝安装。
- 同名目标已存在且无明确覆盖许可：发布必须拒绝。
- 清理没有本次明确许可：只允许预览，不允许删除。

## 4. 恢复规则

1. 启动时读取 Manifest 的最后成功状态。
2. 校验该状态所需产物仍存在且有效。
3. 从下一阶段继续；如果产物损坏，只回退到最近一个有效状态。
4. 参数、来源或目标场景发生变化时，创建新运行，不复用旧运行目录。
5. 不把失败轮次的候选 Skill 发布为正式资产。

## 5. 三轮失败时的交付

只交付候选 Skill 临时目录、冻结测试集、三轮报告、失败检查项和需要补充的证据。除非用户看到风险后明确要求，否则不得安装。
