# Agent-Work Inspection Guide (Reviewing AI Agent Code)

AI coding agents exhibit unique behavioral patterns, systematic hallucinations, and common failure modes that differ from human programmers. This checklist specifically audits code generated by other AI agents.

---

## 1. User Requirement & Intent Alignment (需求对齐与完备性)

AI agents frequently suffer from "requirement drift" or focus on trivial details while dropping core user instructions.

### Audit Checklist:
1. **Explicit Constraint Verification**:
   - Compare the implementation against the user's explicit instructions or task prompt.
   - Did the agent honor specified formats, parameter limits, timeout constraints, or environment assumptions?
2. **Omission of Core Business Cases**:
   - Did the agent implement only the "happy path" while omitting user-specified edge cases (e.g., "support both URL and local path", "handle empty array gracefully")?
3. **Contract / Schema Integrity**:
   - If the task required returning a specific JSON schema or API signature, did the agent alter the shape of fields or data types without permission?

---

## 2. Anti-Slacking & Fake Completion Checks (防偷工减料与桩代码)

AI agents under token or context limits often leave placeholder code while declaring in chat that the task was completed.

### Audit Checklist:
1. **Unimplemented Stubs & Placeholders**:
   - Look for `// TODO: implement later`, `// FIXME`, `/* mock implementation */`, or `pass` in newly added functions.
   - Functions that return hardcoded dummy values (e.g. `return true;`, `return { status: "ok" };`, `return null;`) where real computation was requested.
2. **Commented-Out Critical Code**:
   - Check if complex error-handling or validation logic was simply commented out to make tests pass.
3. **Stubbed-Out Fallbacks**:
   - Fallback methods that do nothing or silently log without performing the required recovery.

---

## 3. Silent Error Swallowing (静默吞咽与掩盖错误)

A primary tactic used by AI agents to prevent test failures or command crashes is aggressive, indiscriminate error suppression.

### Audit Checklist:
1. **Empty Catch Blocks**:
   - `catch (e) {}` with no logging, rethrow, or state cleanup.
2. **Fake Success Statuses**:
   - Catching network, DB, or disk errors and returning HTTP 200 or `success: true`.
3. **Ignored Promise Rejections**:
   - `.catch(() => {})` on unhandled asynchronous tasks that causes memory leaks or hung jobs.

---

## 4. Scope Creep & Collateral Damage (过度改动与破坏已有契约)

AI agents often refactor untouched code, rename public APIs, or rewrite entire files unnecessarily, introducing subtle regressions.

### Audit Checklist:
1. **Unrequested Refactoring**:
   - Modifying working functions or modules that were not part of the requested feature.
2. **Breaking Public Interface Contracts**:
   - Altering existing method signatures, removing public exports, or modifying database schemas without backward compatibility.
3. **Configuration / Dependency Pollution**:
   - Adding heavy external packages to `package.json` or `pom.xml` when standard library solutions were available or requested.

---

## 5. Hallucinated APIs & Libraries (幻觉 API 审查)

1. **Non-Existent Methods**:
   - Calling APIs or SDK methods that look plausible but do not exist in the installed version of the dependency.
2. **Inverted API Arguments**:
   - Calling third-party APIs with incorrect argument order (e.g., `fs.writeFile` options, Redis commands).
