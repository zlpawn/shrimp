# 同步引擎能力画像与路由字典 (Engines Catalog)

`leo-workspace-router` 采用开放式引擎路由设计，针对不同文件与代码协作场景，将请求分发给最适合的底层 CLI。

---

## 🧭 引擎总览表

| 引擎标识 | 适用核心场景 | 工作模式 | 延迟与性能 | 状态 |
| :--- | :--- | :--- | :--- | :--- |
| **`mutagen`** | 远程代码实时双向开发、本地 IDE + 远程运行 | 实时双向监听 + 后台 Daemon | 毫秒级增量同步，极速体验 | **首期已启用 (Active)** |
| **`rsync`** | 一次性工程拉取、发布上线部署、大文件单向备份 | 单向执行完即退出 | 块级增量传输，无需后台守护 | 规划中 (Planned) |
| **`rclone`** | 对象存储、S3、WebDAV、网盘文件迁移 | 单向/双向远程网盘映射 | 受限于网络与云存储 API | 规划中 (Planned) |
| **`unison`** | 去中心化多端常驻同步、复杂冲突双向合并 | 周期/监听双向同步 | 强一致性校验 | 规划中 (Planned) |

---

## 🎯 场景研判与路由规则

1. **场景 A：远程代码实时开发 / 远程构建（命中率最高）**
   * **用户意图特征**：“把本地代码同步到服务器实时跑”、“本地用 Antigravity/VSCode 写代码，远程执行”、“双向同步这个项目”。
   * **目标引擎**：**`mutagen`**
   * **执行策略**：调用 `scripts/engines/mutagen.mjs`，注入智能过滤规则（自动排除 `node_modules`、`.git` 等），拉起静默守护进程。

2. **场景 B：单向快照与部署（非持续性）**
   * **用户意图特征**：“把这个目录打包传到服务器”、“从服务器拉一份代码快照到本地备份”、“部署上线”。
   * **目标引擎**：**`rsync`**（规划中，提示用户或临时调用 rsync 指令）。

3. **场景 C：网盘与云存储传输**
   * **用户意图特征**：“同步到 S3 存储桶 / 阿里云 OSS / WebDAV”。
   * **目标引擎**：**`rclone`**（规划中）。
