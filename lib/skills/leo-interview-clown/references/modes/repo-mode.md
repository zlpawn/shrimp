# 仓库深度模式（`repo`）

当输入为整个代码仓库、微服务、模块或 Monorepo 产品时启用。Phase 1 所有盘点、追踪与草稿均放入 `<run-dir>/extraction/` 和 `<run-dir>/drafts/`，**严禁在审批前改动被分析仓库或目标知识库**。

## 1. 仓库全景测绘（Pass 1）

按需盘点：
- 构建与 Workspace 清单（Monorepo 通过构建配置、import、部署配置、路由和数据流推断服务间关系；仅在多个独立产品同等可能时询问范围）。
- 模块/服务边界与依赖方向。
- API/RPC 路由、MQ 生产者与消费者、定时调度器、事件监听器、回调与 CLI/批处理入口。
- 数据库 Schema、迁移脚本、实体、Repository 与状态枚举。
- 外部系统客户端与集成适配器。
- 前端调用入口、测试、Fixture、已有文档与配置。
- 生成代码、三方库、Mock、纯迁移或疑似废弃代码。

先分类再深挖，严禁直接把目录树报一遍当成项目解读。

## 2. 核心候选识别（Pass 2）

在 `<run-dir>/extraction/coverage-ledger.md` 建立覆盖账本，并输出候选表：
`候选流程 | 业务角色 | 入口 | 数据锚点 | 终态输出 | 核心信号 | 置信度`

挑选能解释产品核心价值的最小流程集合（通常 1–3 条），其余真实域保留在覆盖账本中以防静默遗漏。

## 3. 双向链路追踪（Pass 3）

从高信号入口**正向追踪**，同时从以下位置**反向追踪**：
- 核心表或聚合根
- 终态字段取值
- 用户可见输出与对外发送事件
- 重试、超时、取消、补偿与人工修复记录

只正向追踪会漏掉隐藏写入方和恢复路径；只反向追踪会漏掉业务触发动机。

## 4. 业务重建与 7 类高价值旁路检查（Pass 4 & 5）

对每条核心流程完整还原：
`触发 -> 校验/前置条件 -> 编排 -> 数据/状态变更 -> 外部副作用 -> 输出 -> 成功终态 -> 重试/超时/取消/人工恢复`

状态机必须从**实际写库代码与状态守卫**反推，不能只抄 Enum 常量。同时检查 7 类面试极易追问但常被忽略的工程旁路：
1. 动态规则/配置的生产编辑与运行时消费方式
2. 管理后台或人工修数/修复入口
3. 定时对账与数据清理 Job
4. 审计日志、快照、Outbox/Inbox 与幂等记录表
5. 批量导入导出与历史数据迁移路径
6. 权限校验与多租户隔离边界
7. 支撑线上排障的日志、Trace 与监控可观测性

## 5. 大型仓库分段策略

1. 先全盘摸底所有一级模块；
2. 深挖核心候选主流程；
3. 概括性盘点支撑域；
4. 明确列出未深挖/排除区域——绝不把“抽样看了几个模块”说成“全仓完整覆盖”。

## 6. 生成 Phase 1 提案

应用 `references/core/teaching-and-interview.md`（6 个入门问题、6 类「为什么」深挖、八要素难点卡与反包装自检、面试话术），写入 `<run-dir>/proposal/knowledge-proposal.md`，附带目标目录与拆分/覆盖确认表，等待用户批准。
