# 文档 + 代码混合交叉模式（`hybrid`）

当用户同时提供**设计/架构文档**（飞书/Craft/RFC/技术博客/架构图）与**代码仓库或具体方法**时启用。

## 为什么混合模式在面试中最管用

只看设计文档，面试时容易把“当年规划但没落地的方案”当成线上实现；只看代码，又容易丢失“当初为什么做、面临什么量级约束、压测基线是多少”。混合模式把两者打通，直接暴露文档与代码的漂移。

## 执行步骤

1. **文档采集（`doc` 模式）**：
   - 全量读取正文、表格与核心图片/白板至 `<run-dir>/source/` 与 `<run-dir>/extraction/`。
   - 提炼背景约束、旧方案痛点、演进决策、压测条件与设计主张（标为 `原文声明`）。
2. **代码实证（`repo` 或 `method` 模式）**：
   - 追踪真实入口、数据模型、状态写入、异常重试、并发控制与测试（标为 `直接证实`）。
3. **强制产出「文档 vs 代码交叉比对表」**（提案与最终档案均需包含）：
   | 主题 | 设计文档主张（`原文声明`） | 代码真实实现（`直接证实`） | 结论（`一致` / `文档超前未实现` / `代码已演进偏离` / `存在冲突`） | 面试安全讲法 |
   |---|---|---|---|---|
4. **融合输出**：
   - 用文档补足“业务背景、约束条件与压测口径”；
   - 用代码夯实“精确实现、边界防御、故障恢复与二阶追问细节”；
   - 任何文档与代码不一致之处必须高亮警示，防止面试时踩坑说漏。
