# 小红书视觉设计与图卡生成规约

## 一、视觉调度全权委托机制（由 leo-imagine-router 统一决策）

`leo-xhs-router` 本身不再硬编码任何底层生图引擎，也不维护冗余的视觉决策分支。**所有小红书视觉图卡（封面、内页信息图、架构图、概念海报）的画风匹配与生成调度，统一全权委托给专精视觉路由器 `leo-imagine-router`**。

由 `leo-imagine-router` 根据笔记的内容特质、读者情绪与信息载荷，自主裁决并调用最佳专精画风：

| 笔记类型 / 场景特质 | `leo-imagine-router` 调度专精画风 | 核心美学与呈现 |
| :--- | :--- | :--- |
| **观点金句 / 重磅发布 / 技术评论** | **`mono-color`** | 受控单色/双色印刷（如钴蓝+炭黑），机械网点（Halftone），孔版颗粒，25%~50% 留白与 5x 字阶大字报 |
| **真实硬件 / 极客工位 / 工具实景** | **`scenes-gathered-zine-v1-3`** | 真景为锚，手撕纤维纸毛边，实物照片与矢量大色块背景杂志拼贴 |
| **影像蒸馏 / 极简艺术转译** | **`scene-distillation-zine-v1-3`** | 不保留原像素，提炼人物/环境情感隐喻，独立极简艺术插画海报 |
| **展会见闻 / 旅行光影 / 建筑摄影** | **`photo-abstract-editorial`** | 原图绝对锁定，下方无缝拼接象牙白抽象记忆面板，展签级艺术双联画 |
| **人文摄影 / 街头纪实 / 电影氛围** | **`morandi-cinematic-poster-zeejay`** | 莫兰迪纸基与克制油墨，5大电影排版构型 + 虚构演职员表（Billing Block） |
| **深度代码高亮 / 参数面板 / 对比表** | **`xhs-html`** | 3:4 单文件 HTML 矢量渲染转图，文字 100% 精确，绝不崩字乱码 |
| **通用流程 / 架构拓扑 / 交互时序** | **`built-in-fallback`** | 严格遵循 6 槽位（用途/主体/场景/风格/构图/约束）技术信息图 |

## 二、通用主次视觉层级与 7:3 黄金排版法则（跨题材通用）

小红书是移动端**极速滑屏、高视觉冲击**的中文社区，读者滑屏决策时间仅有 0.3~0.5 秒。
- **纯长文/纯书面痛点**：字多字小，在手机瀑布流中无法在 0.2 秒内解码，直接被读者拇指滑过；
- **纯花哨/无重点痛点**：缺少关键锚点信息，读者抓不住与自己的关联度；
- **通用 7:3 黄金法则**：**70% 核心主视觉（中文大字报、痛点冲击、主观情绪、反差结论） + 30% 辅助标识点缀（英文品牌/术语/坐标点缀/数据单位/微缩微标）**。

### 跨题材通用分工矩阵
| 题材分类 | 70% 中文大字报主标（0.2秒秒懂） | 30% 质感辅助点缀（英文/参数/坐标/微标） |
| :--- | :--- | :--- |
| **技术 / 极客 / 工具** | `内存暴降90%！` / `本地大模型跑通了` | `LIGHTPANDA 1.0` / `30MB vs 500MB` / `BENCHMARK #01` |
| **职场 / 成长 / 故事** | `干了5年，我跑路了…` / `30岁裸辞第100天` | `CAREER INSIGHT // 2026` / `DAY 100 VLOG` |
| **美食 / 探店 / 旅行** | `人均20，吃到撑！` / `30年老店隐藏吃法` | `CHENGDU FOOD GUIDE` / `LOCAL FAVORITE ★★★★★` |
| **商业 / 认知 / 理财** | `90%的人都做反了` / `普通家庭抗通胀指南` | `ASSET ALLOCATION` / `FINANCE NOTE #04` |
| **生活 / 好物 / 测评** | `千万别买！大坑😭` / `出租屋50块神仙改造` | `ROOM MAKEOVER` / `HONEST REVIEW` |

## 三、标准 5 张 3:4 卡片配置范式 (1 封面 + 4 核心内页)

小红书推荐算法对多图笔记给予更高滑屏与停留时长权重。**每篇笔记建议至少生成 5 张 3:4 图卡**：

- **卡片 1（大字报反差封面）**：大中文主标题 + 英文品牌/微标 + 中文痛点冲击钩子。
- **卡片 2（核心参数对比）**：中文指标维度（`内存占用` / `冷启动耗时`） + 英文硬核数据对比条。
- **卡片 3（架构原理解析）**：中文数据流向（`输入` ➔ `极速解析` ➔ `调度`） + 英文核心模块与协议标注。
- **卡片 4（兼容实操与代码）**：英文可复现代码块/命令行 + 中文无痛接入指引。
- **卡片 5（真话清单与坐标）**：中文双栏对照清单（`适合做什么` vs `搞不定什么`） + 底部英文项目官方出处/坐标。

## 四、标准卡片尺寸与排版安全区

- **标准比例**：3:4 竖版（推荐尺寸 `1080 × 1440` px）；
- **安全边距**：
  - 顶部安全区：保留 120px（避免被小红书客户端顶部关注/返回按钮遮挡）；
  - 底部安全区：保留 160px（避免被点赞/收藏浮层遮挡）；
  - 左右内边距：保留 80px。
- **字号阶梯**（以 1080×1440 为基准）：
  - 封面主标题：60px ~ 80px（粗黑体 / 强视觉抓眼球）；
  - 卡片小标题：40px ~ 48px；
  - 正文解释字：26px ~ 32px；
  - 最小文字限度：不低于 22px（手机端清晰可见）。

## 五、纯读者视角品控禁令（非谈判项）

最终放置在 `图片/发布版/` 的所有图片，**必须完全服务于手机端的普通读者**：

1. **严禁工作流痕迹**：严禁出现“参考原文”、“重绘”、“参考重绘”、“制作说明”、“源文链接”；
2. **严禁 AI 工具标签**：严禁出现“AI 生成”、“AI 绘图”、“提示词”、“prompt”、“AIGC”等降低博主真实感的字样；
3. **严禁占位符**：严禁出现“待提供”、“待替换”、“待确认”、“TODO”、“XXX”；
4. **严禁角标页码**：严禁在卡片角落生硬标注“01/06”、“1/6”、“page 2”等创作者标记；
5. **严禁草稿水印**：严禁残留“DEBUG”、“DRAFT”、“草稿”、“内部测试”。

## 六、通用封面双簧工程与文案脱水规约

在输出 `内容.md` 时，必须显式提供 `## 封面文案` 小节，并遵循以下工业标准：

1. **字数硬约束（脱水大字报）**：
   - 封面文案严格限定在 **4~10 个汉字以内**（确保以 60px~80px 粗体占据画面时，在 3 米外依然一眼秒懂）；
   - 严禁将 18 字的系统标题整句照搬到封面上（字小、繁杂、失去冲击力）。
2. **双簧互补模型（不重合冗余）**：
   - **封面文案负责**：抛出反常悬念、情绪共鸣、极端反差或核心利益（如 `“内存暴降90%！”`、`“干了5年我跑路了”`、`“人均20吃到撑！”`）；
   - **系统标题负责**：交代事实主体、人群认领与高频搜索词（如 `开源浏览器实测：这套架构彻底把内存打下来了`）。
3. **视觉画风匹配**：
   - 由 `leo-imagine-router` 依据内容题材自主决定（`mono-color`、`scenes-gathered`、`xhs-html` 等），保持画风与题材调性深度共鸣。
