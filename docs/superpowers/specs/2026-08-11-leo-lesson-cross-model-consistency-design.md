# Leo Lesson to Skill 跨模型一致性设计

## 目标

让不同大模型处理同一课程与同一目标场景时，生成措辞可以不同，但方法论骨架、执行行为、证据边界和放行标准保持一致。

## 设计原则

1. 模型负责语义理解和自然语言表达。
2. 数据契约负责锁定阶段、结构、证据和验收。
3. 课程事实、派生执行规则和模型内容使用稳定 ASCII 标记隔离。
4. 不以“输出文字相同”作为一致性目标，以“行为契约和验收指标相同”作为目标。
5. 候选 Skill 未通过统一门禁时不得发布。

## 固定流水线

```text
视频/字幕/视觉证据
→ intermediate-representation.json
→ methodology.json
→ skill-spec.json
→ 候选 Skill
→ frozen test suite
→ test-report.json
→ 发布
```

`methodology.json` 只描述课程事实。`skill-spec.json` 是跨模型行为锁，固定：

- 唯一目标场景；
- 执行型或指南型；
- 有序工作流步骤；
- 每步输入、动作、输出、检查点；
- 方法论来源 ID；
- 必需要素与反模式；
- 模型允许自由发挥的范围；
- 一致性验收阈值。

候选 Skill 必须携带与外部规范语义相同的 `references/skill-spec.json`。Markdown 只负责向模型和用户说明，不得覆盖规范。

## 决策一致性

使用明确决策表确定：

- 执行型或指南型；
- 场景是否需要拆分；
- 课程检查点或派生门禁；
- 多模态、OCR 和 ASR 的证据优先级；
- 冲突、不确定和缺失信息的处理。

关键边界提供正例、反例和原因，减少不同模型对抽象规则的自由解释。

## 证据层

视觉证据支持：

1. 多模态分析 + OCR；
2. 仅多模态分析；
3. 仅 OCR；
4. 两者均不可用时使用 ASR，并显式标记视觉未审计。

OCR 不承担图表关系、箭头方向或视觉强调的最终解释。多模态与 OCR 冲突时保留冲突，不静默选择。

## 稳定标记

机器校验使用：

- `[COURSE_EVIDENCE]`
- `[DERIVED_TEMPLATE]`
- `[MODEL_OUTPUT]`

中文和 Emoji 可作为人类可读说明，但不作为唯一机器标记。

## 一致性门禁

测试报告必须满足：

- 方法论骨架覆盖率 `1.0`；
- 步骤顺序完全匹配；
- 必需要素覆盖率 `1.0`；
- 反模式覆盖率 `1.0`；
- 无来源方法论数量 `0`；
- 所有开放冲突均被呈报；
- 必需测试通过率 `1.0`；
- 冻结测试集哈希一致；
- 候选 Skill 携带的规范与冻结规范一致。

测试模式记录为 `deterministic`、`self_eval` 或 `independent_eval`。测试模式影响可信等级，但不降低硬指标。

## 可移植执行

- 所有脚本从 `SKILL.md` 所在目录解析，不依赖当前工作目录。
- 支持 Windows、macOS 和 Linux。
- `agents/openai.yaml` 是 OpenAI 宿主适配器，不是 portable 核心必需文件。
- portable 校验只要求 `SKILL.md`、参考资料、稳定标记和行为规范。

## 测试

增加以下回归测试：

- `skill-spec` 引用不存在时失败；
- 步骤顺序漂移时失败；
- 候选携带的规范不一致时失败；
- 一致性指标低于阈值时失败；
- 视觉证据仅多模态、仅 OCR 均可通过；
- 无视觉通道且状态未声明时失败；
- Linux 平台 Manifest 可通过；
- portable Skill 不含 `openai.yaml` 仍可校验；
- OpenAI profile 缺少适配器时失败。

## 范围

本次不实现具体厂商的大模型 API，也不要求不同模型逐字输出一致。重点是提供足够强的数据契约、决策边界、校准样例和统一放行门禁。
